# LNF-SERVER 管理员数据分析模块规则

## 0. 适用范围与最高优先级

本规则仅约束 `agent.md/admin.md` 所述的管理员数据分析模块。执行相关任务时，优先级从高到低为：

1. 本规则中的不可变更、写入边界和人工确认要求。
2. 用户在当前会话中最新且明确的指令。
3. 已确认的模块实施文档 `agent.md/admin_agent.md`。
4. 需求文档 `agent.md/admin.md`。
5. 项目现有代码、文档和惯例。

若低优先级要求与高优先级要求冲突，停止冲突部分，说明冲突，不得自行折中。

### 规则文件不可变更

- `.clinerules/admin-stats.md` 创建后永久只读。
- AI 不得修改、覆盖、移动、重命名、删除或再次生成本文件，也不得创建另一份规则来覆盖、补充或规避本文件。
- 后续发现本规则遗漏或与项目变化冲突时，只向用户报告，由用户手工处理；AI 继续遵守当前文件。

## 1. 写入边界

### 1.1 默认只读

- 除本模块经用户批准的新建文件外，仓库全部只读。
- 不得修改其他成员负责的模块，不得借机重构、格式化、整理 import、修复旁支问题或更新依赖。
- 不得执行 git commit、push、reset、checkout、clean、rebase 等写操作，不得删除任何文件。
- 不得直接连接或修改数据库，不得运行 migration，不得修改或生成 `docs/` 下的 Swagger 产物。

### 1.2 可写文件

阶段 1 经用户批准后，可以新建并持续修改以下管理员统计模块专属文件；实际文件清单必须先写入 `agent.md/admin_agent.md` 并获批：

- `agent.md/admin_agent.md`
- `handler/advanced/admin_stats_handler.go` 及同目录管理员统计测试文件
- `service/advanced/admin_stats_service.go` 及同目录管理员统计测试文件
- `dao/admin_stats_dao.go` 及管理员统计 DAO 测试文件
- `model/advanced/admin_stats.go`
- `router/advanced/admin_stats_router.go`
- `model/mysql/advanced/admin_stats_indexes.sql`，仅在确认确需索引且用户批准后新建

不得用上述文件承载其他模块逻辑。若实际架构要求不同路径，先向用户提出新的完整白名单，获得明确批准后才可新建。

### 1.3 公共文件与既有代码

以下公共入口、配置、响应码、已有文档及已有业务文件均禁止 AI 修改，包括但不限于：

- `config.yaml`、`config.yaml.example`、`go.mod`、`go.sum`
- `main.go`、`initialization/router.go`
- `handler/enter.go`、`service/enter.go`、`dao/enter.go`、`router/enter.go`
- `response/response.go`、`response/response_code.go`
- `agent.md/api_agent.md`、`agent.md/api_guide.md`、`agent.md/common_response_code.md`、`agent.md/admin.md`
- `docs/` 全部生成物
- 已存在的 item、user、announcement、notification、shop、tag、location 等模块文件

若完成集成必须修改公共文件，AI 必须：

1. 保持文件不变。
2. 给出文件绝对路径、定位点、最小修改片段及修改原因。
3. 明确标注“需要用户手工修改”。
4. 用户修改后重新只读检查，再继续验证。

不得通过脚本、格式化器、代码生成器或间接命令绕过写入限制。

## 2. 强制工作流

### 阶段 1：只读调研与设计

编码前必须只读核实代码，并新建 `agent.md/admin_agent.md`，至少记录：

- 当前 admin 路由、角色权限和中间件行为。
- 涉及表、字段、状态流转、软删除规则、现有索引和实际 MySQL 版本。
- 每个接口的 method、完整路径、权限、参数、默认值、互斥规则、响应 JSON、错误码和空数据行为。
- 每项指标的业务定义、时间字段、时区、分子、分母、过滤条件和边界示例。
- DAO 查询方案、预计扫描范围、索引命中评估和 `EXPLAIN` 建议。
- 专属新文件清单、公共文件人工修改清单、测试方案和分批实施步骤。
- 本规则第 3 节中的全部阻塞问题及用户结论。

一次性向用户提交完整计划和待确认问题。未得到明确批准，不得进入编码阶段。

### 阶段 2：按批准批次编码

- 仅实现用户明确批准的批次、接口和口径，不得预埋后续接口。
- 每批结束后运行格式化、模块测试、`go test ./...` 和 `go build ./...`；失败时区分本次变更与仓库既有问题并如实报告。
- 每批提交简报：实现内容、改动文件、测试结果、公共文件人工操作、未决风险。得到用户明确批准后才进入下一批。

### 阶段 3：对照验收

- 对照批准后的接口契约逐项检查代码、Swagger 注释、测试和 `admin_agent.md`。
- 共享 API 文档、响应码和 Swagger 生成物由用户手工同步；AI 只提供精确修改说明并在修改后只读核验。
- 不得因“文档同步”放宽写入边界。

## 3. 已发现的需求问题与阻塞项

以下问题在 `agent.md/admin_agent.md` 中取得用户明确结论前，不得实现受影响接口：

1. **数量不一致**：`agent.md/admin.md` 声称共 11 个接口，正文只列出 9 个 GET 接口和 1 项横切 CSV 能力。不得为凑数自行新增接口。
2. **成功归还不可完全由 status 推导**：代码允许发帖者从 status 0 或 1 自行关闭为 2；自行关闭会清空 `claim_user_id` 和 `claim_time`，确认认领关闭则保留二者。必须确认“成功归还”“已关闭/撤回”的最终口径及历史数据是否足以支持。
3. **`claim_time` 不是完成时间**：该字段在认领时写入，表示认领发生时间；确认或自动关闭时只更新 `updated_at`，不存在独立归还完成时间。不得在未确认前把 `claim_time` 命名为归还时间，或据此声称统计归还完成趋势和真实归还时长。
4. **历史事件会丢失**：撤回认领和自行关闭会清空认领字段，当前 items 快照无法还原完整认领历史。漏斗、归还率和时长若要求事件级准确性，必须先由用户决定接受快照近似，还是另行设计事件记录；不得擅自建表。
5. **权限未定义**：现有 `SystemAdminAuthMiddleware` 仅允许 role=2，`ServiceAdminAuthMiddleware` 允许 role>=1。必须确认 `/admin/stats/*` 面向 role=2 还是 role>=1，并复用对应现有中间件。
6. **时间参数未定义完整**：必须确认 `start_date/end_date` 与 `days` 是否互斥、缺省值、最大跨度、非法日期、开始晚于结束、未来日期和环比基期规则。
7. **时区实现未定义**：业务口径要求东八区；必须确认数据库会话时区及 DATETIME 写入语义。聚合边界应由 Go 计算为明确的 `[start, end)`，不得依赖数据库服务器本地时区猜测。
8. **归还率与环比边界未定义**：必须确认分母、分母为 0、上期为 0、累计值如何计算“较上月环比”，以及百分比精度和舍入规则。
9. **locations 语义未定义**：必须确认按直接 `location_id`、叶子节点还是地点链某层聚合；`location_id IS NULL` 是否单列；percent 分母、并列排序及 `limit=0` 最大数据量必须明确。
10. **中位数依赖数据库版本**：先核实实际 MySQL 版本。不得仅依据 GORM driver 版本推断；不允许在未批准时引入近似算法。
11. **阈值与字段白名单未确认**：stagnant/high-view 的默认天数、浏览阈值、排序并列规则、最大 page_size 和响应字段必须确认；任何响应不得包含 `contact`、用户隐私或内部删除字段，除非用户明确批准。
12. **distribution 与 funnel 未定义完整**：tag 多对多会导致总量重复，必须定义 percent 分母；漏斗各层是否嵌套、按事件时间还是用户 cohort、认领撤回如何处理，必须确认。
13. **CSV 与统一响应冲突**：CSV 文件流无法同时使用 JSON `{code,message,data}` 信封。必须明确 CSV 成功响应的 Content-Type、失败响应、文件名、最大导出范围和超时策略后再实现。

## 4. 项目实现约束

### 4.1 技术与分层

- 使用项目现有 Go 1.26.4、Gin、GORM 和 MySQL，不新增依赖。
- 遵循 `handler -> service -> dao -> model`：handler 只绑定/校验请求并响应；service 负责口径和业务编排；dao 负责查询；model 只放请求、响应和查询 DTO。
- 复用现有 `response.SuccessWithData`、`response.FailWithCode` 和通用错误码。统计查询通常只需 `CodeParamError(1)`、`CodeUnauthorized(2)`、`CodeServerError(5)`、`CodeDatabaseError(6)`；确需新错误码时，由用户手工登记公共响应码文件后再使用。
- JSON 接口保持 HTTP 200，成功 `code=0`，失败 `data={}`。CSV 行为按用户确认的例外契约执行。
- 路径位于项目 `/api/v1` 前缀下，Gin 参数使用 `:param`，不使用 `{param}`。

### 4.2 查询正确性

- 所有 items 统计默认显式包含 `is_deleted = 0`，不得依赖隐式 scope。
- 使用半开时间区间 `[start, end)`，避免 DATETIME 精度导致 `23:59:59` 边界遗漏；输出日期按已确认的东八区自然日补零。
- 金额、计数和 ID 使用足够宽的整数类型；百分比和平均值需明确精度，不用二进制浮点做隐式展示舍入。
- 分页查询必须使用稳定排序，主排序字段相同时以 `id` 作为最终排序键；页码和 page_size 要有上限。
- 列表查询只选择批准的字段，不复用包含 `contact` 的完整 `ItemResponse`。
- 对空集合、NULL、除零、无上期数据、并列排名和被删除关联记录编写明确行为与测试。
- 不拼接用户输入生成 SQL 列名、排序或 dimension；使用枚举白名单映射到固定查询。

### 4.3 性能与成本

- 优先使用数据库聚合和单次批量查询，禁止 N+1 查询和将全表加载进 Go 内存后统计。
- 先评估现有索引。新增索引必须对应实际 WHERE/GROUP BY/ORDER BY，记录预期收益与写入成本，并由用户手工执行。
- 对可能全量返回的 `limit=0` 和 CSV 导出设置经用户确认的时间跨度/行数保护；CSV 必须分批读取、流式写出、定期 flush，不落盘。
- 批次 1、2 可共享经过验证的日期范围与过滤构造，但不要建立包罗所有报表的通用查询框架。整体一致性优先，其次可维护性，最后才是开发成本。

## 5. 测试与验证

- 新逻辑必须配套表驱动单元测试；DAO 聚合至少提供可复现的集成测试方案或固定 SQL 样例验证。
- 核心用例至少覆盖：空数据、单日边界、跨月、闰日/月底、软删除、NULL location、认领后撤回、自行关闭、确认关闭、自动关闭、上期为 0、分页边界、非法 dimension 和超大范围。
- trend 必须验证日期补零和顺序；percent 必须验证总和与舍入约定；median 必须验证奇偶样本；CSV 必须验证 BOM、表头、中文文件名、转义、失败响应和流式错误处理。
- 测试不得依赖生产数据库、真实密钥、真实 QQ 服务或修改 `config.yaml`。不得为了让测试通过而修改其他模块。
- 写入后重新读取全部本次新建/修改文件，检查 `git diff --check`，再运行 `gofmt`（仅本模块可写 Go 文件）、`go test ./...`、`go build ./...`。

## 6. 沟通与决策记录

- 发现歧义、代码与文档不一致或范围变化时，先停止受影响部分，将相关问题一次性集中提出。
- 不得虚构需求、数据库版本、数据分布、测试结果或用户决定。
- 每个用户结论记录到 `agent.md/admin_agent.md`，包含日期、原问题、最终口径和受影响接口。
- 若用户要求违反本规则的写入边界或要求 AI 修改本规则，明确指出必须由用户手工完成；其余不冲突工作可继续。
